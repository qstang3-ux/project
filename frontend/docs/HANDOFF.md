# 前端开发交接说明

## 目标

使用 React + TypeScript + Vite 实现“经管之星”前端。正式行为以前端需求和 OpenAPI 为准。

## 核心交付

- 主框架和侧边栏。
- 智能问数欢迎页、会话列表、输入和消息区域。
- 数据源选择。
- 执行步骤、SQL、结果表格、柱状图和折线图。
- 模型配置及连接测试界面。
- 应用开场白和推荐问题配置。
- 数据错误反馈和回复校对。
- 加载、空数据、错误和安全拒绝状态。
- 生产构建通过，至少一条主链路 E2E。

## 路由

```text
/qa
/qa/logs

/settings/models（兼容旧地址，重定向到 `/settings/application`）

```

## 推荐实现顺序

1. Vite、TypeScript strict、路由和主题 Token。
2. 根据 OpenAPI 生成类型并建立 API Client。
3. 使用契约 Mock 完成页面骨架。
4. 实现问数状态机和完整消息卡片。
5. 接入真实后端并移除组件内部 Mock。
6. 完成配置和反馈页面。
7. 补测试、异常状态和生产构建。

## 主动澄清状态

- `awaiting_input` 是正常可交互等待态，不展示为 SQL 失败。
- 回答卡展示后端返回的 prompt、意图、规范化问题、缺失槽位和当前/最大轮次；所有内容按纯文本渲染。
- 回答卡不包含独立输入框；页面底部的主 `QuestionComposer` 在等待态切换为“补充信息”模式并提交澄清，避免页面同时出现两套输入控件。
- 补充信息通过 `POST /qa/executions/{executionId}/clarifications` 提交，幂等键由 execution ID、澄清轮次和内容哈希稳定生成。
- 补充后继续原 execution/checkpoint，不创建新会话或新 execution。同一 execution 的回答卡只渲染一次，并锚定在最后一条相关用户补充消息之后。
- 刷新页面时会从消息的 `awaiting_input` 执行状态恢复澄清卡；用户可在等待期间确认取消。
- 真实模式订阅 `clarification.required` SSE 事件，SSE 不可用时保留执行详情轮询降级。
- 契约 Mock 覆盖第一轮、第二轮、刷新恢复、重复提交、取消和安全拒绝。Mock 只在 `sessionStorage` 保存无 SQL/无结果的等待态快照。
- 2026-09-21 交互收口：澄清卡只展示提示、缺失槽位与轮次，底部主输入框切换为补充模式；刷新恢复、双击防重、第二轮和取消均由 E2E 覆盖。当前前端门禁为 64 项 Vitest、11 项 Playwright 全部通过。

## 页面滚动

- `AppShell` 固定为一个视口高度，设置页只由 `.app-content` 滚动，避免 document 与内容区双重滚动。
- 应用配置底部操作栏回到正常文档流，不再使用 sticky 或负 margin；只有滚动到配置末尾才显示保存操作，不会遮挡推荐问题和“问数能力”卡片。

## SSE 可靠性

- 前端使用可取消的 fetch SSE 传输层解析命名事件和事件 ID，重连游标通过 `lastEventId` query 参数传递。
- 同一事件 ID 只刷新一次；收到 `execution.completed`、`execution.failed` 或 `execution.cancelled` 后立即关闭连接。
- 非终态断流按 300 / 700 / 1500 ms 最多重连 3 次，之后保留 1 秒执行详情轮询兜底，不产生浏览器原生无限重连。
- 重连前检查游标；410 `SSE_EVENT_EXPIRED`、非法游标或 execution 不匹配时清空游标、全量刷新并重新首连。
- `clarification.required` 暂停重连，补充提交后在原 execution 恢复。execution 切换、组件卸载和 React StrictMode 重挂载都会取消请求、计时器和监听器。
- 当前活动 execution 在 `queued`/`running` 时显示回答 Loading；完成后仅对新回答播放一次短时打字机动画。
  历史恢复不播放，`prefers-reduced-motion` 下直接显示全文。
- 契约 Mock 覆盖断线续传和 410 回退。2026-09-17 真实 `127.0.0.1:8000` 验证首连收到 7 条事件，以 `:1` 重连只返回 `:2` 到 `:7`，临时会话已删除。
- 2026-09-18 最终门禁：ESLint、TypeScript、生产构建均通过，Vitest 28 个文件 55 项通过，Playwright 10/10 通过；E2E 已覆盖断线续传、游标去重、410 全量恢复、宽屏问答/窄屏模型表布局、快捷提问/收藏/日志闭环、表格图表联动、图表类型切换，以及编辑分支、重新生成、回答版本、CSV 与 PNG 下载。

## 接口约束

- 契约位置：`backend/docs/api/openapi.yaml`。
- 后端未完成时只能根据该契约建立 Mock。
- 请求状态必须覆盖 loading、empty、error、success。
- SSE 已作为主通道接入；达到重连上限或临时不可用时保留状态轮询降级。
- 不允许前端自行推断后端数据库字段。

## 浏览器语音

- `sttEnabled` 开启时，支持 Web Speech API 的 Chrome/Edge 展示麦克风按钮；使用 `zh-CN` 单次识别，结果只追加到问题框，不自动提交。
- `ttsEnabled` 开启时，回答卡使用设备 `speechSynthesis` 朗读，优先中文音色，并支持停止与卸载清理。
- 语音不经过本项目后端、不保存音频，不产生额外 API 调用费；浏览器可能使用其平台识别服务，兼容性和可用性由浏览器环境决定。
- 不支持或权限失败时给出明确提示并继续使用文字问答。云端、自托管、流式语音和实时打断仍不在当前范围。

## 快捷提问与问答日志

- 问答输入区已接入快捷提问弹层，支持“常问/收藏”切换；点击问题只回填输入框，不自动提交，并支持关闭、Escape 和点击外部收起。
- 每条用户问题提供收藏/取消收藏操作，收藏结果与快捷提问列表共享缓存并及时刷新。
- `/qa/logs` 已接入真实日志列表、关键词/用户/状态/时间筛选、分页和详情抽屉。
- 日志详情展示执行/请求 ID、意图、规范化问题、数据源、查询对象、SQL 校验、Token、LangGraph/checkpoint、RAG、模型调用和节点轨迹；不推断 OpenAPI 未提供的回答正文。
- 2026-09-17 真实后端联调通过：常问列表、收藏新增/删除、日志列表和日志详情均可用，临时收藏已清理；抽样日志含 4 个节点轨迹和 2 次模型调用。
- 问答日志表格拥有独立纵向滚动区，分页器固定在表格滚动区外；表格高度按最新 UI 验收减少 80px，页面外层不产生二次滚动。

## 编辑分支、重新生成与导出

- 用户消息支持就地编辑、取消恢复原文和重新发送；重新发送调用 `POST /qa/messages/{messageId}/resubmit` 创建新会话分支，不覆盖原消息和原执行。
- 完成态回答支持重新生成；调用 `POST /qa/messages/{messageId}/regenerate` 创建新 execution，进行中禁用相关操作。
- 回答版本抽屉调用 `GET /qa/messages/{messageId}/versions`，可从原回答或任一再生成回答解析同一版本链，展示模型、耗时、生成时间、图表类型、回答和 SQL。
- 有结果行的完成态回答提供 CSV 图标下载，直接使用 `GET /qa/executions/{executionId}/export` 返回的 UTF-8 CSV 和文件名。
- 图表工具栏提供 PNG 图标下载，使用 ECharts 2 倍像素白底快照；文件名会清理 Windows 非法字符。
- 契约 Mock 与 Playwright 覆盖编辑分支、重新生成、版本 1/2、当前版本标识，以及 CSV/PNG 实际下载事件。

## 回答可信度与数据联动（2026-09-18）

- 完成态数据回答在正文前展示最多 3 个答案要点，只复用结果集首行、已有字段和行数，不在前端推导新的经营数字。
- “为什么是这个答案”按需展开规范问题、已授权数据源数量、查询对象和结果规模；不展示思维链，也不把技术审计信息伪装成业务解释。
- 表格行与图表数据点共享高亮索引；鼠标悬浮或键盘聚焦表格行时，图表同步高亮并显示 Tooltip，移开后恢复。
- 图表支持柱状图、折线图和饼图的纯前端快捷切换，不产生新模型调用或数据库查询；缺少必要字段时禁用对应类型，分类超过 12 项时禁用饼图并说明原因。
- 结果表格的金额、整数和百分比右对齐并使用等宽数字，日期居中，文本左对齐。
- 推荐追问优先使用后端真实模型返回的问题；后端未返回时仅按图表类型提供保守的探索建议，点击后仍只回填输入框，不自动发送。
- 回答卡减少嵌套底色，使用细分割线、轻量指标块和悬浮反馈建立层级。

## 回答审计与设置页收口（2026-09-18）

- 回答卡底部展示本次执行总 Token，悬浮可查看输入、输出与总量；数据直接来自 `ExecutionDetail.tokenUsage`，不在前端估算。
- 数据回答固定按“执行过程 → 要点/依据/SQL → 表格 → 图表 → 回答正文”排列；生成中的回答占位也位于末尾，避免图表已经出现但页面中段仍显示 Loading。回答正文不再额外显示“分析结论”标题。
- 执行步骤仅在后端提供可信正数耗时时展示耗时，未知耗时不再显示误导性的 `0ms`。
- 侧边栏只保留“系统设置”；模型配置作为应用配置中的能力卡片，通过齿轮直接打开模型管理弹窗，不再跳转独立页面。旧 `/settings/models` 地址重定向到应用配置。
- 模型管理弹窗以“智能问数模型”场景卡选择当前模型，并用紧凑列表管理已接入模型，不使用宽表格。
- 已保存的 API Key 在前端完全不可见（包括掩码）；编辑模型时默认只显示“已安全保存”，用户主动点击“更换 API Key”后才出现空的密码输入框。
- 对话开场白与其他能力使用同一张卡片样式，卡片保留启用开关，齿轮弹窗编辑欢迎语和推荐问题；修改后自动保存。
- 应用配置取消页面底部保存/取消按钮，字段修改后 650ms 自动保存；连续修改会串行提交并使用服务端返回的新版本号，顶部状态展示等待、保存中和已保存。
- 常问频次阈值已收进“常问问题”卡片的齿轮弹窗，不再平铺在主页面。
- 默认分析年份已从应用配置和 API 契约移除；问题缺少年份且无法从上下文确定时由 Agent 发起澄清。
- 应用配置已重做为统一设置页视觉：状态头、欢迎与推荐区、能力卡片、紧凑参数区和固定操作层级。
- 回复校对页取消固定最大宽度，表格随主内容区铺开，仅保留页面和卡片的必要内边距。

## 安全红线

- 不保存或显示完整 API Key。
- 回答正文支持安全的 GitHub Flavored Markdown；不解析原始 HTML、不加载模型返回的远程图片，也不使用未经清洗的 HTML。
- SQL 只读展示，不提供自由编辑执行入口。
- 图表只解释后端结构化配置，不执行动态脚本。
- 用户、模型和数据库内容都按不可信文本处理。

## 不做范围

- 登录、用户、权限、驾驶舱、台账管理、云端/自托管语音服务及实时语音对话。
- 云端/自托管语音与实时语音对话仍延期；编辑分支、多版本切换、CSV 与 PNG 导出已完成。
