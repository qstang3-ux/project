# 开发流程

## Ready Gate

开始业务编码前必须满足：范围冻结、指标/数据字典、Schema、OpenAPI、验收集、SQL 安全、评测集、环境变量和 Backlog 已基线化。本文档集已满足该基线；实现时若改动需更新对应文档。

## 分支与提交

- `main` 始终可发布；短生命周期 `feature/<issue>-<name>`。
- Conventional Commits：feat/fix/refactor/test/docs/chore。
- PR 必须关联需求编号，列出验证方式、截图/API 示例、迁移和风险。

## Done

- 实现、测试、类型/Lint、Review、文档、迁移及 Docker 验证完成。
- 无明文密钥、无未校验 SQL 路径、无 S0～S2 缺陷。
- 需求验收条件通过。

## 变更

- ≤0.5 人日且不改架构：项目负责人批准。
- 0.5～2 人日：替换同等优先级工作。
- >2 人日或影响数据/API/安全：ADR + 重新排期。
# Agent 沟通门禁

- 所有开发和协调任务必须给出非空回复。
- 跨任务派发采用“发送 → 等待 → 验证非空反馈”的闭环。
- 空回复按一次失败运行处理：自动重试一次；再次为空则由协调任务兜底报告，并记录为空回复异常。
- 没有状态变化时使用“暂无新变化”，不能以空消息代替。
- 状态报告必须区分：已运行验证、历史验证记录、正在执行、等待依赖和真实阻塞。
