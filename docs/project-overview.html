01项目总览

面向经营分析人员的自然语言问数与审计平台

2026-09-21 已校准

FastAPI契约驱动 API、统一错误、幂等和审计

核心价值

可信

模型不直连数据库；候选 SQL 必须通过 AST、对象白名单、只读账号、LIMIT 与超时。

可解释

展示规范化问题、查询对象、执行步骤、SQL、结果表格、图表及业务结论。

可审计

Request ID、Token、模型调用、RAG 文档、节点轨迹、checkpoint、版本与反馈均可追溯。

一句话理解：它不是让大模型自由查询数据库，而是让模型负责“理解问题和生成候选内容”，由程序负责权限、检索范围、SQL 安全、执行、数字核验、状态恢复和最终审计。

→

→

意图体系

data_query、clarification、business_definition、product_help、chat、out_of_scope、unsafe。

只有数据查询进入 RAG/SQL；“今年销售额怎么样”等缺少分析范围的问题由确定性规则兜底进入澄清。

RAG 与上下文

使用 BGE 中文 512 维 Embedding，pgvector cosine 与关键词融合。补充项目数量口径并支持未变化但被禁用文档的重新启用，扩展集 Top-5 召回达到 100/100。

预算与恢复

显式 recursion limit、模型调用/HTTP attempt/总 deadline 预算；checkpoint 连接具有有界超时，租约、心跳和 effect ledger 防止重复副作用。

SQL 安全闸门

阶段规则失败处理
对象选择数据源白名单 ∩ RAG 召回对象 ∩ 模型 selectedObjects交集为空则拒绝
语义归一化仅按白名单规则规范枚举后缀、月度分组和单数最高项归一化后仍须通过完整 AST 校验
AST 校验仅单条 SELECT / 只读 CTE；校验 Schema、表、列、函数安全拒绝，不纠错
执行text2sql_ro、只读事务、超时、行数与响应体上限分类错误并脱敏
纠错仅允许语法、列名和类型等可恢复 SQLSTATE，最多一次纠错 SQL 重新完整验证
答案数字必须来自问题、结果或 rowCount；图表字段必须存在结构或语义无效时最多重新生成一次，仍失败则返回明确错误或程序化降级

关键业务口径

合同额 ≠ 收入

合同额来自合同主表；收入来自按日期发生的确认事实。签约不代表当期已确认收入。

收入 ≠ 回款

回款是独立现金事实；应收需按合同口径比较合同额、累计收入与累计回款，不能混用。

注意视图粒度

v_sales_performance 是“合同 × 月”粒度；跨月汇总重复的合同额或累计值会造成重复计算。

固定验收数据规模

经营单元行业产品线客户合同收入事实回款事实目标商机
2183606001,8001,20042180

固定 Seed：20260915；经营数据截止日：2026-05-31。这些数据用于可重复验收，不代表生产容量上限。

一致性与安全设计

幂等

幂等键绑定 operation、resource 和请求 SHA-256 指纹；占位与业务对象同事务写入。

终态竞争

使用条件 UPDATE/CAS；取消不会被迟到的模型或 SQL 完成结果覆盖。

SSE 重放

事件 append-only，sequence 与 dedupe key 唯一；过期游标通过 sequence floor 返回 410。

六项关键设计说明

1. 契约统一

以 OpenAPI 为唯一接口事实来源，前端类型自动生成。

2. 模型边界

模型负责意图判断、候选 SQL 与总结建议，不直接访问或修改数据库。

3. SQL 受控

对象三方交集、AST 白名单、只读账号、超时和结果上限共同约束。

4. 执行可恢复

execution、checkpoint、lease、effect ledger 与持久事件共同提供恢复能力。

5. 请求幂等

幂等键绑定 operation、resource 与 body fingerprint，终态更新使用 CAS。

6. 答案可核验

模型输出继续经过数字、字段、rowCount 和图表引用校验。

安全边界、质量结论、风险与建议阅读顺序

Review 结论

当前没有未关闭的 S0/S1/S2 代码缺陷。本轮真实模型专项发现的 BE-004～BE-011 已完成修复与针对性复验；LLM、SQL、数据库和 UI 之间的信任边界保持清晰，关键状态可追溯。

密钥安全

API Key 仅通过运行时 Secret 或后端加密存储；前端、响应和普通日志不保存明文。

Prompt 安全

当前问题、历史、RAG、候选 SQL、错误和结果均进入不可信数据面，不能覆盖 system 规则。

前端安全

无未经清洗 HTML；Markdown、图表、语音、日志和澄清均按安全文本或结构化数据处理。

剩余风险

P1 · 干净 Linux 生产机仍需最终验收

Windows Docker Desktop 的开发全栈已从空环境跑通；生产编排的 Secret、数据库角色、迁移和后端镜像也已验证。正式发布前仍需在目标 Linux 主机验证域名、Caddy 自动 HTTPS 和长连接。

P2 · Caddy 镜像运行验证受网络影响

生产 Compose 和 Caddy 配置已静态校验；本机拉取 Caddy 镜像时 Docker Hub 匿名令牌请求两次 EOF，因此本轮未完成 Caddy 容器运行验证。

P2 · 前端生产分包仍有体积提示

ECharts 与主入口存在超过 500KB 的 chunk；当前功能不受影响，后续应依据首屏指标继续拆分。

P2 · npm 审计镜像差异

默认镜像缺少 audit endpoint；使用官方 npm registry 的生产依赖扫描结果无已知漏洞。

推荐 Review 路线

  1. 从端到端请求主链路确认各层职责与调用边界。
  2. 核对 OpenAPI 与 API → Service → Repository/Text2SQL 分层。
  3. 检查意图分类、主动澄清、RAG 对象交集和 SQL Validator。
  4. 检查幂等指纹、租约、终态 CAS、effect ledger、SSE 重放。
  5. 用模型报告、RAG/Prompt 安全评测和自动化质量门禁验证结论。
  6. 明确区分“本机容器通过”和“目标 Linux 生产发布通过”。
