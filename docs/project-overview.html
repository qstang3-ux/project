05后端与 Agent 设计

确定性工作流包围模型的不确定性

FastAPI + LangGraph

分层职责

  • API：校验、依赖注入、HTTP/SSE 映射
  • Service：业务用例、事务边界和状态协调
  • Repository：平台数据持久化，不做业务决策
  • Text2SQL：检索、模型、验证、执行和答案核验
  • Core：配置、日志、错误和密钥安全

API 资源

  • 数据源、会话、消息、执行与 SSE
  • 澄清、取消、重发、再生成、版本与导出
  • 常问、收藏、模型配置与连接测试
  • 应用配置、反馈校对、问答日志
  • 存活和就绪健康检查

统一要求：Request ID、稳定错误码、分页结构、幂等键和脱敏响应。

LangGraph 节点

load_context加载可信历史
→
build_memory抽取结构化槽位
→
classify_intent意图与缺失信息
→
retrieve混合 RAG
→
generate候选 SQL
→
validateAST 与对象交集
→
execute只读查询
→
summarize总结与图表
→
verify / persist核验与落库

意图体系

data_query、clarification、business_definition、product_help、chat、out_of_scope、unsafe。

只有数据查询进入 RAG/SQL；闲聊与帮助不访问数据库。

RAG 与上下文

使用 BGE 中文 512 维 Embedding，pgvector cosine 与关键词融合。Schema、指标、Join 和 Few-shot 按不可信引用传入模型。

预算与恢复

显式 recursion limit、模型调用/HTTP attempt/总 deadline 预算；checkpoint、租约、心跳和 effect ledger 防止重复副作用。

SQL 安全闸门

阶段规则失败处理
对象选择数据源白名单 ∩ RAG 召回对象 ∩ 模型 selectedObjects交集为空则拒绝
AST 校验仅单条 SELECT / 只读 CTE；校验 Schema、表、列、函数安全拒绝，不纠错
执行text2sql_ro、只读事务、超时、行数与响应体上限分类错误并脱敏
纠错仅允许语法、列名和类型等可恢复 SQLSTATE，最多一次纠错 SQL 重新完整验证
答案数字必须来自问题、结果或 rowCount；图表字段必须存在返回明确错误或程序化降级

一致性与安全设计

幂等

幂等键绑定 operation、resource 和请求 SHA-256 指纹；占位与业务对象同事务写入。

终态竞争

使用条件 UPDATE/CAS；取消不会被迟到的模型或 SQL 完成结果覆盖。

SSE 重放

事件 append-only，sequence 与 dedupe key 唯一；过期游标通过 sequence floor 返回 410。

源码阅读入口：backend/docs/data/database-design.md、data-dictionary.md、metric-definitions.md、schema-review-map.md、Alembic migrations。

07Code Review 细节

安全边界、质量结论、风险与建议阅读顺序

2 个发布前环境项

Review 结论

现有 Review 报告未发现会导致危险 SQL 执行、密钥泄露、前端脚本注入或问答主流程不可用的 S0/S1/S2 代码缺陷。LLM、SQL、数据库和 UI 之间的信任边界清晰，关键状态可追溯。

密钥安全

API Key 仅通过运行时 Secret 或后端加密存储；前端、响应和普通日志不保存明文。

Prompt 安全

当前问题、历史、RAG、候选 SQL、错误和结果均进入不可信数据面，不能覆盖 system 规则。

前端安全

无未经清洗 HTML；Markdown、图表、语音、日志和澄清均按安全文本或结构化数据处理。

Findings

P1 · 容器运行时尚待实机闭环

Docker Desktop 与 CLI 已安装、Compose 静态配置通过；Windows 重启后仍需完成 Engine、镜像构建、健康检查、空卷迁移/Seed/RAG 和 Nginx SSE 的完整验证。

P1 · 迁移管理员连接需独立配置

发布环境应通过 Secret 注入 MIGRATION_DATABASE_URL，不能提升应用账号权限，也不能把管理员连接写入仓库。

P2 · 前端生产分包仍有体积提示

ECharts 与主入口存在超过 500KB 的 chunk；当前功能不受影响，后续应依据首屏指标继续拆分。

P2 · npm 审计镜像差异

默认镜像缺少 audit endpoint；使用官方 npm registry 的生产依赖扫描结果无已知漏洞。

推荐 Review 路线

  1. OpenAPI 与 API → Service → Repository/Text2SQL 分层。
  2. 意图分类、主动澄清、RAG 对象交集和 SQL Validator。
  3. 幂等指纹、租约、终态 CAS、effect ledger、SSE 重放。
  4. 模型报告、RAG/Prompt 安全评测和自动化质量门禁。
  5. 明确区分“静态配置通过”和“目标环境部署通过”。
