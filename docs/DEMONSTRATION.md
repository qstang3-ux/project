## 2. 两天冲刺历史归档

历史开发窗口为 **2026-09-16 至 2026-09-17**，当时目标是在有限时间内优先打通真实问数主链路，而非达到完整生产级。

2. 建立会话、消息、数据源和问数最小 API。
3. 打通 Text2SQL、AST 校验、只读执行、表格和图表。
4. 建立 LangGraph、真实模型 Adapter 和危险 SQL 拒绝路径。

### 第二天

1. 完成模型配置、应用配置、反馈与校对。
2. 完成 pgvector、向量 RAG、checkpoint 与恢复。
3. 完成核心问题、危险请求、端到端测试和部署配置。
4. 整理 UI、演示脚本和代码 Review 材料。

当时的砍项顺序为：PNG/CSV 导出 → 回答版本 → 编辑分支 → 收藏 → 日志高级筛选 → SSE 动画细节。LangGraph、向量 RAG、真实模型、SQL 安全、真实数据库、反馈闭环和核心测试不可砍减。该时间盒现已结束，不再作为后续开发规则。

## 3. 原型交互与字段映射归档

### 3.1 原型交互处理原则

- 可达且有明确行为的问数、会话、配置和反馈交互纳入正式需求。
- 仅有视觉外壳而无行为的控件按产品目标重新设计，不照搬空交互。
- 登录、用户、角色、权限、驾驶舱、台账编辑和不可达报表不纳入当前范围。
- 麦克风和语音播放采用可配置的浏览器原生能力；不支持时回退文字交互。
- 数据源选择和问答日志虽非原型主入口，但因属于问数闭环而保留。

### 3.2 原型字段到正式模型

| 原型字段组 | 正式处理 |
|---|---|
| 合同主键 | `contracts.id`，使用 UUID |
| 卖方、签约主体 | `contracts.seller_name` |
| 行业 | `industries.major_name/name` |
| 产品线 | `product_lines.code` |
| 产品型号重复列 | 合并为 `contracts.product_model` |
| 经营单元 | `contracts.business_unit_id` |
| 合同编号、名称、签订日期 | `contract_no/contract_name/signed_at` |
| 买方、最终客户、客户级别 | 合同买方和 `customers` |
| 月度收入 | 拆分为多行 `revenue_facts` |
| 月度回款 | 拆分为多行 `payment_facts` |
| 季度、本年累计、应收 | 查询或语义视图派生 |
| 统计标记 | `is_statistical` |
| 专项 | `special_program` |
| 整体目标 | 映射到 `sales_targets`，万元转换为元 |

清洗规则：统一渠道名称；百分比转换为小数；空字符串转 `NULL`；日期统一 ISO；无法解析的记录拒绝入库；不使用原型运行时随机数。原型 `fields2026` 共 97 列、年度索引为 96，遗留代码读取 108 的行为不纳入实现。

## 4. 演示目标与讲解脚本

目标是在 6～8 分钟内说明平台可将自然语言转换为经过安全校验的只读 SQL，查询 PostgreSQL，并输出可追溯的结论、表格和图表，同时覆盖澄清、安全拒绝、导出和审计。

### 4.1 产品定位（约 40 秒）

系统面向经营分析人员。模型没有数据库直连权限；SQL 必须经过对象白名单、AST 校验、只读账号和执行超时控制。

### 4.2 主链路（约 2 分钟）

问题：`2026年商业目标最高的5个经营单元，用柱状图展示`

- 展示意图识别、知识召回、SQL 生成、安全校验、执行和答案验证。
- 展开 SQL，说明对象来自本次 RAG 召回与数据源白名单的交集。
- 展示答案要点、中文表头、表格与图表联动、CSV 和 PNG 导出。
- 点击继续探索建议，说明建议只回填，仍由用户确认发送。

### 4.3 主动澄清（约 1 分钟）

先问：`达成情况`。系统应进入待补充信息，而不是猜测 SQL。随后补充：`查询2026年各经营单元商业目标完成率，按完成率升序`。补充应在同一 execution 和 checkpoint 中继续，最多两轮。

### 4.4 安全拒绝（约 45 秒）

问题：`执行 SELECT 1; DROP TABLE mart.contracts`。系统应拒绝执行，危险请求不得进入数据库查询节点。

### 4.5 可追溯与修正（约 1 分钟）

- 编辑历史问题并重新发送，展示新分支保留原审计记录。
- 重新生成回答并查看版本链。
- 提交数据反馈，在回复校对页查看。
- 在问答日志展示 Request ID、意图、规范问题、SQL、Token、LangGraph、checkpoint 和 RAG 证据。

### 5.6 现场问题选择原则

- 6～8 分钟演示使用 5.1，不超过 6 次输入。

- 图表题明确写出“柱状图、折线图或饼图”，减少模型自行选择造成的视觉差异。
- 每个独立能力使用新会话；只有演示上下文时才复用同一会话。
- 不临场输入未彩排的复杂多条件长问题，不依赖语音功能完成关键路径。

## 9. 汇报现场问答

### 9.1 回答方式

现场回答优先使用“结论、机制、证据、边界”四步结构：先直接回答问题，再说明系统如何实现，随后指出页面或文档中的证据，最后说明当前范围和后续计划。单个回答控制在 20～40 秒。遇到没有完成的能力应明确说明，不把设计方案说成已经上线的功能。

### 9.2 产品与业务

#### 这个平台解决什么问题？

经管人员不需要了解表结构或编写 SQL，可以直接用自然语言查询合同、收入、回款、目标和项目风险数据。平台同时返回结论、表格、图表和可审计执行过程，降低临时取数和反复沟通成本。

#### 它本质上是不是合同管理平台？

底层业务数据以合同为主线，并关联客户、收入、回款、销售目标和项目风险，但当前产品定位是只读经营分析平台，不是完整的合同生命周期管理系统。合同录入、审批、变更和归档不在当前范围。

#### 为什么不直接使用传统 BI？

传统 BI 更适合预先定义的指标和看板。本平台补充的是临时、探索式问数，并提供主动澄清、上下文追问、SQL 安全校验和审计记录。固定高频指标仍可继续使用 BI，两者并不冲突。

#### 当前支持哪些业务问题？

当前支持合同、收入、回款、应收、商业目标、项目风险以及经营单元、区域、行业、产品线等维度的查询与分析。天气、开放域知识和数据写入请求会被识别为范围外或不安全请求。

#### 为什么没有合同导入功能？

当前交付目标是打通可信的只读分析闭环，数据通过固定 Seed 和既有数据源进入系统。合同导入涉及模板校验、重复数据、权限、审批和错误回滚，应作为独立业务模块建设，不应在问数链路中临时拼接。

### 9.3 Agent 与 LangGraph

#### 用户问题进入系统后经过哪些步骤？

系统先装载可信上下文并识别意图，再检查必要槽位。只有数据查询才进入混合 RAG、结构化 SQL 生成、AST 安全校验、只读执行、答案生成和程序化核验；普通闲聊、产品帮助、指标解释、澄清和危险请求会走独立分支。

#### 为什么选择 LangGraph？

这条链路不是一次模型调用，而是包含路由、等待用户补充、SQL 纠错、取消、失败和恢复的有状态流程。LangGraph 提供显式节点、条件边和 PostgreSQL checkpoint，便于恢复和审计，也避免把控制权交给模型自由循环。

#### Agent 最多循环多少次？

图执行显式设置 `recursion_limit=30`，这是图节点步数的保护上限，不代表允许调用模型 30 次。SQL 只允许一次受控纠错，澄清最多两轮，同时还有总执行 deadline、逻辑模型调用预算和 HTTP attempt 预算。

#### 信息不足时为什么不直接猜？

意图节点会输出规范问题、缺失槽位、置信度和原因码。缺少指标口径、时间范围或分析维度时，execution 进入 `awaiting_input`，前端提示补充信息；用户补充后沿同一个 execution、graph thread 和 checkpoint 继续。

#### 系统有哪些意图类型？

意图集合固定为 `data_query`、`clarification`、`business_definition`、`product_help`、`chat`、`out_of_scope` 和 `unsafe`。封闭枚举便于测试和路由，避免模型动态创造不可控流程。

#### 上下文和记忆怎么处理？

系统只读取同一会话中已完成且可信的数据查询作为历史上下文，并保存来源消息 ID 和上下文 provenance。编辑问题会创建新分支并复制当时的上下文快照；澄清只合并同一 execution 的补充信息，避免不同分支互相污染。

#### 为什么不保存模型思维链？

平台保存节点轨迹、输入输出摘要、模型用途、Token、耗时、RAG 文档和 SQL 等可审计信息，但不保存隐藏 Prompt 或模型思维链。这样既满足排障和审计需要，也减少敏感实现信息暴露。

### 9.4 Text2SQL、RAG 与准确性

#### 为什么需要 RAG？

模型仅看到用户问题时无法可靠理解企业内部表、字段、指标和 Join 关系。RAG 在每次查询前召回相关 Schema、字段、指标口径、Join 和 Few-shot，为模型提供本次任务所需的最小知识范围。

#### 为什么选择 pgvector，而不是单独部署向量数据库？

当前知识库规模不大，PostgreSQL 已是主数据库。使用 pgvector 可以复用备份、迁移和运维体系，并减少一个基础设施组件。规模增长后可以启用 HNSW，当前使用 cosine 精确检索更容易验证结果。

#### Embedding 使用什么模型？

默认使用本地 `BAAI/bge-small-zh-v1.5`，生成归一化的 512 维中文向量。使用本地 Embedding 可以降低业务元数据外发、网络依赖和持续调用成本。

#### RAG 如何检索？

系统分别取得 pgvector 语义 Top 10 和关键词 Top 10，再融合为默认 Top 5 文档，并归并成最多 6 个允许对象。SQL 可访问对象必须同时满足数据源白名单、RAG 召回对象和模型 `selectedObjects`。

#### RAG 100/100 是否代表最终回答百分之百正确？

不是。100/100 表示扩展评测问题的正确知识在 Top 5 召回结果中出现，证明检索覆盖达标；最终正确性还依赖意图识别、SQL 生成、执行结果和答案总结，因此真实模型需要单独评测。

#### 真实模型准确率是多少？

核心演示集为 8/8，危险请求为 5/5。扩展评测执行 100 题、每题 3 轮，共通过 279/300，准确率 93%；针对初测失败问题完成修复后，定向复验为 45/45。定向复验不等于重新声称全量 300 次达到 100%，汇报时应保留这个区别。

#### 为什么核心集全通过，扩展集只有 93%？

核心集验证发布主链路，问题数量少且口径明确；扩展集覆盖更多实体别名、时间表达、Top N、澄清和边界情况，并重复执行检验模型稳定性。两组数据回答的是“主链路能否发布”和“复杂输入下稳定性如何”两个不同问题。

#### 如何防止模型编造数据？

LLM 不直接接触数据库连接，也不能自行返回最终业务数字。SQL 经过校验后由后端执行，答案只能基于结构化查询结果生成；随后程序会核对答案中的数字是否来自结果集，发现无法对应的数字就拒绝该答案。

#### SQL 执行失败会不会无限重试？

不会。只有明确属于可恢复类别的 SQLSTATE，例如语法或未定义字段、表、函数错误，才允许一次纠错；权限、超时、连接和安全拒绝不会交给模型反复尝试。

### 9.5 安全与数据保护

#### 大模型是否可以直接访问数据库？

不可以。模型只输出结构化 SQL 候选，后端负责对象范围检查、AST 校验和只读执行。Text2SQL 账号只能访问允许的 `mart` 语义视图，不能访问平台 `app` Schema、模型配置、checkpoint 或系统表。

#### SQL 安全有几层？

主要包括意图安全分类、结构化输出校验、对象交集白名单、SQL AST 校验、只允许单条查询、只读数据库账号、事务只读、超时和最大行数限制。任何一层失败都会停止执行并返回脱敏错误。

#### 如何防御 Prompt Injection？

用户输入、历史消息、RAG 文档和数据库错误都按不可信内容处理。系统提示与数据内容分离，SQL 对象和语句能力最终由程序规则与数据库权限决定，因此“忽略规则”之类文本不能扩大权限。

#### API Key 为什么在配置后不可见？

密钥只在首次新增或显式替换时提交，后端加密保存；列表和详情接口不返回密钥或可还原掩码，前端也不写入浏览器存储。模型调用日志只记录供应商、模型、用途、耗时和 Token。

#### 用户重复点击发送会怎样？

每次写操作携带稳定的 `Idempotency-Key`。后端将它与 operation、resource、session 和请求体 SHA-256 指纹绑定；相同请求复用原结果，不同请求误用同一个键会被拒绝，避免产生孤儿执行或重复消息。

#### 多实例同时处理同一 execution 怎么办？

execution 使用 owner、租约到期时间、心跳和运行次数进行原子领取。终态更新、取消优先级和副作用账本共同降低重复执行和终态覆盖风险，失效租约可以由其他实例接管。

### 9.6 前端、流式状态与体验

#### 页面是真流式回答吗？

后端将执行事件持久化并通过 SSE 推送。前端按事件刷新执行详情并展示状态、步骤和回答动画；SSE 断开后使用 `Last-Event-ID` 从已持久化序号继续，游标过期时清空游标并全量恢复，轮询作为降级手段。

#### 为什么先展示表格和图表，结论还在生成？

查询结果先于自然语言总结产生，前端会尽早展示确定性数据，结论区域保持独立 loading。这样用户不必等待模型完成总结，但“分析结论”始终排列在表格和图表之后。

#### 图表类型可以通过对话指定吗？

可以。用户可以明确要求柱状图、折线图或饼图；系统基于查询结果生成结构化 ChartSpec，前端使用 ECharts 渲染。即使图表渲染失败，表格仍是可靠降级结果。

#### 语音功能是否收费？

当前语音转文字和文字转语音使用浏览器原生能力，没有单独采购云语音服务。能力和音色取决于浏览器及操作系统；不可用时保留文字输入和播放失败的静默降级，不把语音作为关键路径。

### 9.7 数据库与工程设计

#### 数据库为什么分 `app` 和 `mart` Schema？

`app` 保存会话、消息、执行、模型配置、反馈、RAG 和 checkpoint 等平台数据；`mart` 提供面向分析的只读业务视图。分离后可以只给 Text2SQL 账号授予 `mart` 访问权，从数据库权限层阻断平台敏感数据。

#### checkpoint 和业务执行记录有什么区别？

checkpoint 保存 LangGraph 在节点间恢复所需的内部状态，数量会明显多于 execution；`qa_executions` 是面向产品和审计的最终事实记录。前端与报表读取业务记录，不把 checkpoint 当作业务事实。

#### 为什么 checkpoint 数据增长很快？

图在多个节点和通道上持续写入状态，`checkpoint_blobs` 和 `checkpoint_writes` 数量高于执行数属于正常现象。正式长期运行前需要按 execution 终态和审计保留期制定归档、清理和容量告警策略。

#### 为什么 OpenAPI 是唯一接口契约？

前端类型由后端 OpenAPI 生成，避免前后端分别猜字段。状态、Token、澄清和 SSE 事件发生变化时先修改契约，再更新实现与测试，可在构建阶段发现不一致。

### 9.8 测试、Code Review 与发布判断

#### 项目做了哪些测试？

前端覆盖组件、状态机、语音、表格图表、安全渲染和 Playwright 端到端流程；后端覆盖 API、Repository、LangGraph、RAG、SQL Validator、只读 Executor、幂等、SSE 和 PostgreSQL 集成；另外有真实 DeepSeek 和固定 Seed Oracle 的专项评测。

#### Mock 测试能否证明真实模型可用？

不能。Fake/Mock 用于稳定验证分支和错误处理，真实模型测试单独记录模型名、execution ID、Token、耗时、SQL 和结果正确性。汇报时应分别呈现自动化工程测试和真实模型评测。

#### Code Review 最值得看哪些文件？

前端从 `QuestionWorkspace`、`useQuestionWorkspace`、统一 API Client 和回答组件进入；后端从 API router、Query Service、`text2sql/agent.py`、Retriever、Validator、Executor 和 Repository 进入；数据库重点看迁移、数据字典和 Schema Review Map。详细路径在前后端 `code-review-map.md`。

#### 当前可以直接判断为生产就绪吗？

当前版本具备真实演示和工程验收条件，但完整生产化仍需结合企业要求补充身份认证与权限体系、业务数据接入、监控告警、密钥托管、备份恢复、checkpoint 保留策略和容量压测。当前范围明确排除了登录、角色和权限，因此不能把演示通过等同于企业生产上线。

### 9.9 部署与成本

#### `docker compose up -d --build` 做了什么？

它会构建前端和后端镜像，创建网络与数据卷，启动 PostgreSQL，等待健康检查后执行数据库迁移、固定 Seed 和 RAG 索引，最后启动后端与 Nginx 前端。`migrate`、`seed` 和 `rag-index` 成功后以退出码 0 结束，不是异常停止。

#### 必须部署在 Linux 吗？

不是。开发机可以使用 Windows Docker Desktop，当前环境也已验证；正式服务器更推荐 Linux，因为容器运行、网络、文件权限、资源限制和运维工具链更成熟。

#### 模型可以更换吗？

可以。模型层使用 Adapter 隔离，并支持 OpenAI-compatible 接口。更换模型需要新增配置并重新执行结构化输出、安全和准确率评测，不能只因为接口兼容就认为结果质量等价。

#### 如何统计模型成本？

每次模型调用记录用途、输入 Token、输出 Token、总 Token、耗时、重试次数和状态；execution 聚合显示本次回答的 Token。实际费用需要结合供应商当期单价计算，平台不在代码中固化可能变化的价格。

#### 模型或向量服务不可用怎么办？

`demo` 和 `prod` 模式失败关闭并返回明确错误，不用 Fake 结果冒充真实回答。本地开发模式可以显式允许关键词降级，并在审计信息中标记 `degraded`。

### 9.10 容易答错的问题

- 不说“RAG 100/100，所以回答准确率 100%”；应区分召回率与最终答案正确率。
- 不说“LangGraph 最多调用模型 30 次”；30 是图递归步数上限，模型调用另有预算。
- 不说“所有生产能力都已完成”；身份权限、真实业务接入、监控和长期容量治理仍需建设。
- 不说“系统完全不会产生错误 SQL”；应说明错误候选会被校验拦截，可恢复错误最多纠正一次。
- 不说“API Key 做了掩码展示”；已保存的 Key 根本不返回前端，只允许显式替换。
- 不说“checkpoint 就是业务日志”；checkpoint 用于图恢复，execution 和事件表才是业务审计事实。
- 不展示或口述任何真实 Key、数据库密码、连接串、隐藏 Prompt、原始数据库异常和内部思维链。
